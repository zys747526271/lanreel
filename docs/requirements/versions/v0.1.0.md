# v0.1.0 版本需求

- **版本**：v0.1.0（首个可运行版本）
- **对应里程碑**：M1、M2、M3、M4、M5、M5.1
- **基线需求**：原始需求文档 v3.1（[original/REQUIREMENTS-v3.1.md](../original/REQUIREMENTS-v3.1.md)）
- **状态**：已交付（详见 [completed/v0.1.0.md](../completed/v0.1.0.md)）

## 1. 版本目标

把需求文档中的「局域网随机视频流媒体系统」落地为**可在浏览器直接使用的完整前后端**：

1. 部署一个二进制即可提供服务，前端静态资源内嵌（N-18）。
2. 普通用户：注册 / 登录 → 抖音式竖滑浏览 → 收藏 → 跨设备同步。
3. 管理员：策略（文件夹 / 文件 / 时间窗口）+ 用户管理 + 审计 + 运行日志检索。
4. 前后端分类日志分别落本地日志库，可检索、可导出、可清理。

## 3. 范围外（Out of Scope，本版不做）

| 项 | 原因 | 去向 |
|----|------|------|
| 视频转码 / 压缩 / 服务端缩略图生成 | 避免 CPU 飙升影响前台游戏（N-04、第 8 章风险） | backlog B-01 |
| Tauri PC 套壳（F-32） | 依赖前端稳定后再套壳，不影响 Web 端交付 | backlog B-02 |
| 手机 App / 电视端客户端（F-33） | 需独立选型，API 已预留 | backlog B-03 |
| 文件系统事件监听（inotify / ReadDirectoryChangesW） | 首期用定时扫描满足 F-05，事件监听属优化 | backlog B-04 |
| 登录失败限流 / 防爆破 | 局域网场景优先级低，需先定义策略 | backlog B-05 |
| 日志远程聚合、GraphQL/gRPC 网关、PostgreSQL 适配 | 属第 9 章扩展点，非首期目标 | backlog B-06 |

## 4. 验收标准

版本验收以「可运行 + 可观测」为准，以下每条均需实际执行而非推断：

1. **构建**：`make build` 产出 `dist/lanreel.exe`（含前端资源，单文件）。
2. **启动**：`dist/lanreel.exe --config config.yaml` 后 `/api/v1/health` 返回 `status=ok`、`db_ok=true`。
3. **浏览**：浏览器访问根路径 → 登录页；登录后进入全屏滑动，视频自动播放（静音起步），图片按配置秒数自动切换。
4. **Range**：`curl -H "Range: bytes=0-99" .../stream` 返回 `206` + `Content-Range`，响应头含 `Cache-Control`、无 `Set-Cookie`。
5. **策略**：禁用文件夹后普通用户随机流不再返回该目录内容、直接访问流地址返回 `403`；管理员预览仍为 `200`；收藏条目保留并标记 `out_of_time_window` / `disabled_by_admin`。
6. **收藏**：收藏后换一个浏览器（或清空本地缓存）登录同一账号，收藏列表一致。
7. **后台**：策略变更、用户变更均出现在审计日志；运行日志可按分类 / 级别 / 关键字 / 请求 ID 检索。
8. **日志隔离**：`data/lanreel.db` 与 `data/logs.db` 为两个独立文件，日志库版本号独立维护。
9. **资源**：空闲进程内存 < 50MB（实测 28MB，`GOMEMLIMIT=200MiB` 场景）。
10. **回归**：`go test ./...`（media / policy / config 包）通过，`go vet ./...` 无告警。

# CR-001 策略继承语义、访问日志粒度与缩略图约定

- **提出时间**：2026-11-24
- **类型**：需求澄清 + 新增约定（原始文档未明确）
- **状态**：已实现（v0.1.0）
- **影响范围**：策略判定、后台展示、日志量、缩略图接口

## 1. 背景

实现过程中发现原始需求 v3.1 有三处表述需要收敛，否则不同人会做出不同实现：

1. **F-12 / 9.4**：只写了「文件夹策略 + 最长前缀匹配」，未说明**根目录**（`folder_path` 为空）策略对子目录是否生效。
2. **F-36 / 10.2**：要求记录访问日志，但媒体流播放时每个 Range 请求都会产生一条访问日志，会快速淹没日志库。
3. **F-16 / 第 8 章**：说明「首期不做服务端缩略图生成」，但 `thumb` 接口需要明确的返回值与文件约定，否则接口行为不确定。

## 2. 变更内容

### 2.1 根目录策略作为全局默认（继承语义）

- **决定**：`folder_path = ""` 的策略视为**全局默认策略**，对未单独配置的子目录生效；子目录策略按最长前缀覆盖上级策略。
- **理由**：管理员最常见的操作是「一键关掉全部内容」或「全局只在夜间开放」，若根目录策略不向下生效，则必须逐个目录配置，与实际使用不符；同时最长前缀匹配本身已隐含层级语义。
- **影响**：
  - `policy.Evaluator.MatchFolder` 明确该语义，并补充单元测试。
  - 后台「文件夹策略」页对未单独配置但被上级覆盖的目录显示「继承『根目录』」，避免误读为默认允许。
  - 接口新增字段：`inherited`、`inherited_from`（新增字段不破坏旧客户端，符合 9.2）。

### 2.2 访问日志按路径分级

- **决定**：`/api/v1/media/:key/stream` 的访问日志降为 `debug` 级别，其余 API 保持 `info`；播放期间的关键事件（拒绝播放、媒体缺失）仍以 `info`/`warn` 记录在 `media` 分类。
- **理由**：一次视频播放可能产生数十次 Range 请求，`info` 级别会造成日志库无效膨胀（与 N-23、N-28 的资源目标冲突）。
- **影响**：默认 `info` 级别下日志聚焦业务与异常；排查播放问题时可临时把级别调到 `debug`（后台可热切换，N-26）。
- **访问日志文案**：消息体统一为 `METHOD PATH STATUS`（如 `GET /api/v1/media/random 200`），结构化字段仍写入上下文。

### 2.3 缩略图接口约定

- **决定**：
  - 图片：`/media/:key/thumb` 直接返回原图（带缓存头），前端负责按需裁剪/模糊。
  - 视频：读取 `{data_dir}/thumbs/{video_key}.jpg|png|webp`，存在则返回，否则 `404 thumb_unavailable`，前端使用渐变占位。
  - 不可播放的条目不在此接口做模糊处理，由前端 `filter: blur()` 实现（符合第 8 章风险说明）。
- **影响**：为后续缩略图生成（backlog B-01）预留稳定的存放路径与接口契约，前端无需改动。

## 3. 兼容性

- 三个变更均为**行为澄清或新增字段**，不修改既有请求/响应结构，`/api/v1/` 版本号不变。
- 已按 `docs/requirements/completed/v0.1.0.md` 的验证方式实测：
  - 根目录策略禁用后，未配置的子目录内容同步不可见；
  - 普通用户直接访问被策略拦截的流地址返回 `403`，管理员仍为 `200`；
  - 恢复策略后 5 秒内（缓存 TTL）生效。

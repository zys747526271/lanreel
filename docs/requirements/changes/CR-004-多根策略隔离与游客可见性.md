# CR-004 多根目录策略隔离与游客可见性

- **提出时间**：2026-11-24
- **类型**：需求补齐（B-07）+ 新增角色需求（用户提出「不登录也能看」）
- **状态**：已实现并实测
- **影响范围**：数据库结构、策略判定、媒体接口鉴权、后台策略页、前端浏览页

## 1. 背景

1. **B-07**：文件夹策略以「源内相对路径」为键，配置多个媒体根目录时，不同根下的同名目录（如各有一个 `sub`）
   会共享同一条策略，无法分别控制。
2. **游客**：原实现的媒体接口全部要求登录，用户输入 IP 后必须先注册才能看内容。实际使用中，
   局域网家人/访客只想随手看看，注册是多余门槛；同时管理员需要「游客能看 A、登录用户能看 A+B」这种分层。

## 2. 变更内容

### 2.1 策略按「根索引 + 相对路径」隔离

- `folder_policies` 新增 `root_index`，唯一键改为 `(root_index, folder_path)`；
  `root_index = -1` 表示**全局默认策略**，对所有根生效。
- 迁移 `0002_multi_root_guest.sql`：原 `folder_path = ''` 的策略迁移为 `-1`（保持"一键全局"的既有语义），
  其余保留在 0 号根；旧客户端无需改动。
- 判定顺序：文件级覆盖 > 同根最长前缀 > 全局默认策略（-1）> 默认允许。
- 媒体条目新增 `root_index` / `root_name`；后台文件夹页按根分组，每个根固定一行「整个根目录」。

### 2.2 游客（未登录）浏览

- `/media/random`、`/media/:key/stream`、`/media/:key/thumb` 改为可选鉴权：
  无令牌按游客处理；带令牌但失效返回 401（避免把已登录用户静默降级）。
- 策略新增 `guest_enabled`（文件夹与文件级都有）：游客看 `guest_enabled`，登录用户看 `enabled`，
  时间窗口两者共用。默认 `guest_enabled = true`，与「输入 IP 就能看」的预期一致。
- 收藏、设置等账号功能仍要求登录；游客点击收藏会引导到登录页。
- `GET /config/public` 增加 `guest_access`。

## 3. 兼容性

- 已有实例升级后：原「根目录策略」变为全局默认，单根实例行为不变；多根实例需在后台按根单独配置（这正是 B-07 要解决的）。
- 新增字段均为**追加**，`/api/v1/` 不变；旧前端不会读取新字段。

## 4. 验证记录

| 场景 | 结果 |
|------|------|
| 旧库升级 | 自动应用 0002；原 `folder_path=''` 策略变为 `root_index=-1`，媒体数与账号正常 |
| 双根同名目录隔离 | 禁用 `root0:sub` 后，`root1:sub/yellow.png` 仍可见；管理员可见全部 |
| 直连被禁文件 | 普通用户与游客均 `403` |
| 游客 / 普通用户分层 | `root1:旅行` 设 `enabled=true, guest_enabled=false`：游客看不到 `旅行/mountain.png`，登录用户可见 |
| 游客随机流 | 无令牌 `GET /media/random` 返回游客可见条目 |
| 游客收藏 | `GET /media/random?mode=favorites` 返回 `401`，前端引导登录 |
| 游客页面 | 顶栏显示「游客」与「登录」，可直接滑动浏览 |

## 5. 未纳入

| 想法 | 处理 |
|------|------|
| 独立游客账号 / 游客收藏 | 游客为匿名身份，无持久数据；收藏仍属登录用户 |
| 按游客限速 / 限并发 | 局域网场景暂不需要，公网暴露时再评估 |

# 需求管理（LanReel）

本目录是 LanReel 的需求单一事实来源。所有需求变更、版本范围、完成情况与遗留事项都在这里留痕，
代码仓库只依赖这些文档进行验收，不另行维护散落的需求说明。

## 目录职责

| 目录 | 职责 | 维护时机 |
|------|------|----------|
| `original/` | **原始需求快照**，只增不改。每次拿到新版本需求文档，新增一个带版本号的文件 | 收到新需求文档时 |
| `versions/` | **每个版本的需求范围**：目标、范围边界、验收标准、交付物 | 版本启动时冻结，变更走 `changes/` |
| `completed/` | **已完成需求**：逐条对应原始编号（F-xx / N-xx），含实现位置与验证方式 | 版本验收通过后 |
| `backlog/` | **未完成需求**：本版未做 / 部分实现 / 后续版本规划，含原因与前置条件 | 版本验收时同步更新 |
| `changes/` | **新增需求（变更请求 CR）**：原始文档未覆盖、实现过程中发现并确认的新增或修订需求 | 需求确认后立即编号归档 |

## 编号与状态约定

- 需求编号沿用原始文档：功能需求 `F-01`…`F-43`，非功能需求 `N-01`…`N-29`。
- 原始文档未覆盖的新需求使用 `CR-<序号>`，并在 `changes/` 下建独立文件；
  若被纳入某版本，则在 `versions/vX.Y.Z.md` 中引用 CR 编号。
- 状态取值（`completed/`、`backlog/` 统一使用）：

| 状态 | 含义 |
|------|------|
| ✅ 已完成 | 功能可用，且已按文档中的验证方式实测通过 |
| 🟡 部分完成 | 主流程可用，但存在明确的未覆盖点（在备注中写清缺口） |
| ⬜ 未开始 | 尚未实现，或无外部依赖无法开工 |
| ➖ 不适用 | 与当前阶段目标冲突，或已被其他方案替代（需说明替代方案） |

## 变更流程

1. 提出：在 `changes/` 新建 `CR-00X-<短标题>.md`，写清背景、变更内容、影响范围（接口 / 数据 / 前端）。
2. 评估：确认是否破坏现有接口契约（`/api/v1/` 前缀保持不变，破坏性变更需新开 `/api/v2/`）。
3. 归档：纳入目标版本时，在对应 `versions/` 文档的「范围」章节引用 CR 编号。
4. 验收：完成后在 `completed/` 中标注对应 CR 已实现，并在 `backlog/` 移除相关条目。

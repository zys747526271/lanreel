## 二、下一版本候选（v0.2.0 方向）

优先级从高到低，供排期参考：

1. **B-01 缩略图**：直接改善收藏夹与后台文件列表的可用性（当前视频无预览图）。
2. **B-04 文件监听**：降低 NAS 上的无效 I/O，让「放入即出现」体验更好。
3. **B-02 Tauri 套壳**：完成 PC 端交付形态，顺带验证跨端复用。
4. **B-05 登录限流**：多人环境（宿舍 / 办公室）上线前应补。
5. **B-07 多根策略隔离**：仅在用户确实配置多个媒体根目录时必要。

## 三、明确不做（长期）

- 服务端实时转码 / 压缩（与 N-04、低资源占用目标冲突）。
- 社交媒体功能（评论、点赞、关注）：产品定位为私有媒体浏览，不做社区。
- 集中式日志服务 / 云端日志聚合：首期与可预见阶段只落本地日志库。

## 四、已知技术债

| 项 | 说明 | 影响 | 建议 |
|----|------|------|------|
| 日志查询 `keyword` 使用 `LIKE %kw%` | 无法利用索引 | 日志量大（>50 万条）时检索变慢 | 引入 SQLite FTS5 虚表，或限制检索时间范围 |
| 随机流去重依赖客户端传 `exclude` | 客户端可伪造，导致重复率上升 | 仅影响体验，不影响正确性 | 服务端按会话维护最近播放队列 |
| 媒体元数据无文件指纹 | `video_key` 基于路径，重命名后收藏失效 | 重命名文件会丢失收藏关联 | 增加「内容哈希」二级索引（成本较高，按需启用） |
| 前端无自动化测试 | 当前靠端到端脚本手工验证 | 回归成本高 | 引入 Vitest + Playwright，覆盖登录、滑动、收藏、策略拦截 |
